УСТАНОВКА В TILDA
1. Сделать копию действующей страницы, сохранить старый HEAD и код аналитики.
2. Сохранить действующую глобальную шапку Tilda. Шапка test-preview.html — только для предпросмотра, ее не вставлять в T123. На глобальной шапке настроить меню и CTA по ТЗ.
3. Вставить 02_PAGE_FULL_T123.html целиком в один блок T123. Не разделять style/script или HTML-контейнер между блоками.
4. В настройках SEO страницы задать title, description и canonical из 01_HEAD_SEO.html. Метатеги Open Graph и favicon добавить в HEAD, избегая дублирования тегов, которые уже создает Tilda. Charset/viewport относятся к самостоятельному предпросмотру: не добавлять их повторно в действующий HEAD.
5. Глобальная аналитика 2.1 уже установлена пользователем. Сохранить резервную копию и заменить ее содержимое на 04_POZHARNIK_ANALYTICS_2_2.js в том же теге script HEAD. Не добавлять второй экземпляр. Новая версия сохраняет названия pz_* и ключи хранения атрибуции. Скрипт страницы использует enrichAllForms и совместимое событие tildaform:aftersuccess только после подтвержденного приема заявки серверным адаптером. Проверить 2.2 на копии страницы до замены глобального кода.
6. До подключения отправки утвердить полную политику оператора и URL политики. Встроенное краткое окно не заменяет полную политику.
7. Настроить серверный адаптер CRM и затем добавить конфигурацию из 03_CONFIG_EXAMPLE.html ДО скрипта T123. Изменять только значения настроек, ключи CRM не вставлять в HTML.
8. Публиковать только готовую страницу. Не публиковать все страницы проекта с черновиками.
9. Проверить полный сохраненный T123, UTF-8, формы, контакты, модальные окна, мобильную панель, аналитические события и одну запись CRM/BigQuery на заявку.

СЕРВЕРНЫЙ КОНТРАКТ ФОРМЫ
Этот пакет использует предусмотренный обновленным ТЗ серверный адаптер для собственной формы T123. Он не использует скрытую имитацию штатных приемщиков Tilda и не копирует идентификаторы приемщиков со старых страниц.
leadEndpoint — HTTPS адрес согласованного обработчика, принимающего POST application/x-www-form-urlencoded.
Он проверяет обязательные поля, согласие, регион, услугу, формат телефона; ограничивает злоупотребления; создает один лид Bitrix24 и независимо пишет аналитику BigQuery. Секреты только на сервере.
Для подтвержденного приема возвращает HTTP 2xx и JSON:
{"accepted":true,"lead_id":"CRM_ID","response_time_text":"Утвержденный срок ответа"}
lead_id обязателен. Ответ одного аналитического приемщика не считается созданием лида CRM. Если создание лида идет через надежную очередь, lead_id должен быть постоянным идентификатором принятой заявки и обработчик обязан гарантировать доставку.
Повтор с тем же event_id не создает второй лид. Новый запрос пользователя получает новый event_id. После тайм-аута идентификатор сохраняется для безопасного повтора.
Обработчик разрешает CORS только для согласованных доменов опубликованного сайта. Произвольный endpoint из URL пользователя не принимается.
Не назначать известный Cloud Run BigQuery URL как leadEndpoint без проверки, что он действительно выполняет контракт CRM и возвращает принятый lead_id.
До задания leadEndpoint и policyApproved=true форма проверяет поля и сообщает о недоступности онлайн-отправки. Она не делает сетевых запросов и не показывает ложный успех. Телефон и WhatsApp работают.

ТАРИФЫ И КАЛЬКУЛЯТОР
Без утвержденных тарифов калькулятор показывает необходимость обследования либо расчета по проекту. Цены не выдуманы.
Для предварительной вилки заполнить priceRules только на основании согласованной коммерческой модели. Пример структуры в 03_CONFIG_EXAMPLE.html не содержит цен.
Для оборудования/сложных объектов модель по м² не заменяет техническую смету; при отсутствии применимой модели оставить вывод обследования.
Отображение результата не является quote_sent. Бизнес-события qualified_lead, visit_done, quote_sent, contract_won отправляет CRM, не браузер.

МАТЕРИАЛЫ И ОТЛИЧИЯ ОТ ПОЛНОЙ ПРИЕМКИ ТЗ
Контакты взяты с https://pozharnik.kz/kontakty, пакеты названы по обновленному ТЗ. Состав пакетов является структурой предложения; его нужно согласовать с продажами до публикации.
Изображения — превью реальных опубликованных видеоматериалов Pozharnik.kz, а не фотографии работ и не шесть разных объектов. Они явно так подписаны. Для полной приемки заменить/дополнить их шестью реальными фото работ и тремя-пятью подробными кейсами с подтвержденными площадями, сроками и результатами. Сейчас вместо неподтвержденных кейсов показаны реальные обследования и отзывы.
Перед финальной публикацией загрузить согласованные фото/превью в отдельную папку Tilda и заменить HTTPS URL изображений на реальные HTTPS CDN-URL Tilda. Имена медиа должны быть уникальны для главной. Не заменять ссылки выдуманными URL. Локальных C:\ или assets/ ссылок в T123 нет.
Лицензия 23028116.jpg оформлена на ТОО Archer Project. Связь с оператором Pozharnik.kz не подтверждена предоставленными файлами. Ее скан с адресом и кодами не опубликован, а лицензия не названа собственной лицензией Pozharnik. Для блока лицензий нужны подтвержденная юридическая связка, область действия и согласованный обезличенный JPG/WebP.
Неподтвержденные «10 лет», «500 объектов» и гарантии отсутствия штрафов не использованы. Панель доказательств пока содержит направления и результаты работ без выдуманных метрик.
Узкие новые URL из медиаплана не подставлены как будто готовые: действия идут в форму с выбранной задачей. Действующие страницы пакетов и контактов доступны отдельными ссылками. После создания посадочных добавить ссылки в карточки и сохранить CTA расчета/выезда.
Видео в MP4 не встраивается: согласованного MP4 до 20 секунд и менее 5 МБ нет. Видео открывается по явному действию пользователя на YouTube.
В HEAD пока нет og:image и apple-touch-icon: добавить после получения согласованных материалов, не указывать несуществующие файлы.

АНАЛИТИКА
События страницы: pz_calculator_start, pz_calculator_complete, pz_package_select, pz_contact_click, pz_form_error.
Глобальный модуль обеспечивает pz_cta_click, pz_form_start, pz_form_enriched, pz_form_submit, pz_form_success. Для успешной собственной формы страница передает совместимый aftersuccess либо, без модуля, одно pz_form_success.
Настроить GTM для дополнительных событий; они не становятся Primary Google Ads.
Собственная форма сохраняет источник CTA, не заменяет его кнопкой submit. При наличии utm_last_json очищает несовместимые first-touch click ID из плоских last-touch полей; first-touch остается в JSON. gaMeasurementId позволяет запросить client_id через gtag get с резервом текущего модуля.
В приложенной версии 2.2 исправлены null при отсутствии CTA, подсчет посещений на внутренних переходах, обновление last-touch при внешнем входе, смешение click ID из разных касаний и перезапись CTA служебными кнопками. Сессия хранится в sessionStorage вкладки, тайм-аут — 30 минут. Исторические счетчики 2.1 автоматически не пересчитываются. Для gtag get задать gaMeasurementId через window.PozharnikAnalyticsConfig либо PozharnikHomeConfig до модуля. Действующий сайт автоматически не менялся; заменить глобальный файл при установке и выполнить сквозные тесты. Дополнительная проверка долгого бездействия, нескольких вкладок и ограничений браузерного хранилища нужна до полной приемки.
Полная приемка включает 10 тестовых лидов по пяти ICP, перенос ID до Сделки, ICP-score, роботы и офлайн-конверсии. Без доступа к CRM это не проверено и не объявляется выполненным.

ЛОКАЛЬНЫЙ ПРЕДПРОСМОТР
Открыть test-preview.html в браузере или запустить preview-server.mjs через Node. Адрес сервера http://127.0.0.1:4173/. Самостоятельный предпросмотр не включает действующий GTM и не отправляет реальные лиды.

ИСХОДНИКИ
page.html, page.css, page.js, build.py — редактируемые исходники. build.py собирает HEAD, T123 и предпросмотр. Онлайн-настройки передаются через window.PozharnikHomeConfig. Для установки использовать HEAD, T123, настройки, исправленную глобальную аналитику и инструкции. Самостоятельный test-preview.html не подключает аналитику и реальные приемщики.
